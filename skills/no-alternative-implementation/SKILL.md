# 代替実装の禁止・停止条件

## 目的

指定された要件を満たせない場合に、AIエージェントが勝手に代替実装へ進むことを防ぐ。

このSkillは、演出・機能・成功条件・対象ファイルが明示されている作業で必ず参照する。

## 基本方針

指定された要件を満たせない場合、勝手に別の見た目・簡易実装・部分対応へ進まない。

「一部だけできた」は完了ではない。

ユーザーが明示的に許可していない代替案は採用しない。

## 禁止事項

以下を禁止する。

- 指定された演出・機能が未実装のまま、別の見た目や簡易実装で完了扱いにする
- 背景色だけ変更するなど、ユーザーが許可していない部分対応を採用する
- 成功条件を満たしていないのに、実装完了として扱う
- できない理由を報告せず、試行錯誤でCSS・Component・ロジックを増やす
- 指定外ファイルを変更して帳尻を合わせる
- 指定要件を満たしていない状態で、テスト未実行・目視未確認のまま完了報告する
- 代替案を採用した理由を後から正当化する

## 停止条件

以下のいずれかに該当する場合は、実装を停止して報告する。

- 指定された演出・機能を実装できない
- 指定された成功条件を満たせない
- 指定ファイルだけでは実現できない
- 既存構成上、追加ライブラリ・大幅な構成変更が必要になる
- 現在の実装方式では視認性・動作・性能のいずれかを満たせない
- テストまたは確認コマンドで失敗し、原因を解消できない
- 実装対象外ファイルを変更しないと成立しない

## 停止時の報告形式

指定要件を満たせない場合は、次の形式で停止して報告する。

```text
実装できなかった要件:

試した内容:

できなかった理由:

変更したファイル:

元に戻すべき変更:

次に人間が判断すべきこと:
```

## 完了条件

完了報告できるのは、次を満たした場合のみとする。

- 指定された要件を満たしている
- 指定された成功条件を満たしている
- 指定外の代替実装を採用していない
- 変更対象ファイルが説明できる
- 実行した確認コマンド、または未実行理由を説明できる
- テスト・ビルド・目視確認のうち、作業内容に必要な確認が完了している

## 判断基準

AIエージェントは完成判定を勝手に行わない。

要件未達の場合は、実装を続けるのではなく、停止して人間の判断を待つ。

代替実装は、ユーザーが明示的に許可した場合のみ行う。
