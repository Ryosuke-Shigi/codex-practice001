# Team Task Contract

Apply these integrity rules throughout:

- When a resolved issue/clause/location identity recurs, append a new Finding digest and rederive the catalog from every Finding and resolution receipt. Reopen it until the new Finding is resolved; never overwrite earlier evidence.
- After an artifact-changing verified fix, reset current source, completion, approval, and all reports to canonical inactive evidence bound to the new artifact revision. Retain historical staging, require a fresh source introduction, and reject old source/completion reuse.
- Require each reserved transition kind's typed exact causal subset, including exact reason, report phase/kind/status/cause, failure, Finding conflict identity/positions, and canonical input problems. Reject a valid cause when unrelated same-generation Finding, receipt, rejection, blocker, conflict, or report evidence is mixed in.
- Persist only a sanitized input problem projection of input kind, safe field names, and canonical blockers/rejections. Treat a field name containing a personal path, session identifier, secret, token, password, or private marker as private; retain only its generic unknown-field problem code. Never persist the raw key. Bind the projection digest and canonical start authority to the run ID. When the Task Contract has any schema, type, item, empty-value, or path blocker, persist the single schema-valid, value-independent safe rejected Task Contract instead of raw invalid values while retaining the original canonical problem codes. Preserve a valid Task Contract when only an envelope, Registry, or capability problem rejects it. For every redacted new canonical or legacy input, discard the original idempotency key, title, path, and agent; converge on the fixed safe ID and the same safe rejected Task Contract fallback.

1. Collect every canonical field. Do not invent missing terms:
   - identity and intent: `task_id`, `title`, `goal`, `background`, `current_state`, `desired_state`
   - scope: `scope`, `non_goals`, `allowed_paths`, `forbidden_paths`, `affected_domains`, `risk_level`, `required_capabilities`
   - acceptance: `acceptance_criteria`, `constraints`, `source_of_truth`, `required_checks`, `stop_conditions`, `retry_conditions`, `completion_conditions`
   - team and write boundaries: `team_assignment`, `primary_writer`, `consulting_specialists`, `reviewer`, `verifier`, `write_ownership`
   - approval and delivery: `approval_boundaries`, `required_deliverables`, `information_source_sync`
2. Place those 29 fields under `task_contract` in the canonical envelope with `schema_version` and `idempotency_key`. When exact runtime roles are required, add the closed top-level `role_assignments` object with exactly one distinct `writer`, `reviewer`, and `verifier`; missing, multiple, incompatible, unknown, colliding, scope-insufficient, or fixed-Task-Contract-mismatched assignments must block without dynamic fallback or priority selection. Include `schema_version` in every new/resume/write/source entrypoint. Use only project-relative paths. Treat a sensitive resume run ID only as an existing-run routing boundary and do not persist its redaction rejection.
3. Run `python3 scripts/team_harness.py build-contract INPUT.json` from the project root. Stop when the command exits non-zero or emits any blocker.
4. Treat the emitted immutable `task_contract`, its digest, and `human_summary` as deterministic projections of the same input. Never edit one projection independently.
5. Validate configs and the example with `python3 scripts/team_harness.py validate`; the standard-library validator rejects missing fields, wrong types, duplicate items, empty required evidence, nested unknown properties, unsafe paths, and private data. Treat Execution Policy as the only state-graph owner. Keep its version/digest as the Policy artifact pin shared by config, schema, and example; never copy state tables into Python or checker code. Keep the canonical Policy exact: terminal states are `completed`, `failed`, `blocked`, and `cancelled`; write states are only `implementing` and `retrying`; every retry/stop target must have its required transition; final-review retry limit is `needs_human_approval`.
6. Stop on incomplete or ambiguous scope, allowed/forbidden contradictions, unsupported input, traversal or absolute paths, forbidden targets, secrets at any nesting depth, session identifiers, personal paths, role conflicts, unverifiable evidence, or approval-boundary decisions requiring a human.
7. Pass the unchanged validated envelope to `python3 scripts/team_harness.py init-run INPUT.json`. Require one primary writer to cover every contracted domain, capability, and path. Stop if coverage would require aggregation across writers. Issue no write grant in that case. Keep implementation, verification, and review in three ordered waves, and never move excess implementation members into a quality wave.
8. Use only authority grants from a prior committed Run State generation. Require caller-supplied artifact/write or quality grant objects to exactly equal the active persisted grant of the same discriminated type; caller-created, modified, or same-batch reissued grants are invalid. Keep `issued_revision` bound to the commit. Return unknown write authorization as read-only structured not-found before creating a lock. Never present `runtime_authenticity_status: unverified` as runtime enforcement.
9. Treat plan, implementation artifact, or ownership changes as evidence invalidation. Re-run initial verification and review against the new artifact before source staging. Reject every generic transition into `retrying`, into a policy-declared reserved state, or out of `retrying`; only failed/blocked canonical quality processing may enter retry and only the verified fix gate may return retrying work to implementation. Commit an under-limit final-review failure directly from `final_verification` to `retrying` with its report, history, cause counter, drift Finding, and transition in one request, one generation, and one save. Send blocked and retry-limit branches directly to their Policy targets in that generation; enter `final_review` only for a passed report. Never persist a checkpoint or private pending transition. Accept cancellation only through the closed `cancel` event with actor `orchestrator`, a non-empty reason, a Policy-allowed source state, and dedicated cancellation evidence; keep `interrupt` mapped to `blocked`. Treat each runtime event list as an atomic event batch: prevalidate every event and evaluate on a copy. Before saving a Finding-conflict reserved transition, run the same pure typed exact predicate used by storage replay. Return `event_batch_after_reserved` without an exception or persistence when the batch mixes the conflict cause with an unrelated Finding or other evidence. Preserve semantic state, plan, artifact, Finding, attempt, revision, and generation for every atomic rejection.
10. Express custom `required_checks`, `required_deliverables`, retry conditions, and completion conditions as machine-checkable IDs or supported predicates. Enforce artifact receipt authority: accept an artifact only when its caller-supplied write grant exactly matches the prior committed active primary-writer grant, in a write-enabled state, at an exact Task Contract path within Registry scope and active ownership. Persist the raw content, ref, digest, normalized path, and grant binding in the generation commit manifest. At load, enforce receipt path scope against the historical exact grant, Task Contract allowed/include/exclude/forbidden paths, historical ownership, and current Registry writer scope. Require the receipt introduction's prior write-enabled generation to name the same primary writer, ownership revision, lease epoch, grant producer/run/agent/issued revision/digest, and receipt provenance. Never let an out-of-scope or temporally invalid receipt satisfy a check, deliverable, retry, or completion condition. Keep all write ownership on that single primary writer; never issue write grants to read-only Specialists/reviewer/verifier. Trust only verified receipts; never accept a report's string list or caller-supplied receipt as self-attestation.
11. Accept public Finding events only from the assigned reviewer or verifier with matching actor/source, explicit `issue_id`, `clause`, `location`, and `status: open`. Keep every Finding receipt immutable and append-only. After a verified fix, append a resolution receipt bound to one issue identity, original Finding digest, fix artifact receipt, failed report, attempt, cause, and provenance; derive catalog status from the receipt sequence instead of changing the Finding. Preserve each failure history entry as the exact historical Finding identity set for its report digest, phase, and attempt. Bind a fix artifact and resolution receipt only to identities that have that resolution receipt. Resolve only the named issues; never erase unresolved siblings or advance to completion while any issue remains open. Accept failure authority only through a complete canonical quality report; reject the evidence-free public `review_failed` event. Treat `passed`, `failed`, and `blocked` as total report branches, preserve canonical checks in normalized reports and metrics, commit failed report/history/counter/rejection at retry limit, and send final-verification blocked to a terminal stop state. On retry, bind the fix to the failed report digest, normalized cause fingerprint, attempt, plan revision, explicit causally-related issue IDs, immutable input/environment fingerprints, and a diff receipt already persisted with producer/run/contract/plan provenance. Require every Task Contract `receipt:<id>` retry condition in that same verified causal receipt's receipt/check/deliverable ID set. Validate every binding before changing attempt or revision. Bind final-review failures to an open drift Finding and bounded Policy retry. Never use an arbitrary hash or message equality as proof of resolution.
12. Before final verification/review, require the real immutable staging file plus its current content digest, commit-manifest binding, source manifest digest, and committed source revision. At source introduction, require the first accepted generation revision, generation-contained ref, current source/artifact digest, closed target identity, and run/contract/artifact provenance. Exactly carry the approved Task Contract, artifact revision/digest, initial verification/review reports, implementation approval, and not-run final reports into that generation; keep that source basis immutable until disappearance makes a later staging a new introduction. Permit no report change in `source_sync`, only final verification in `final_verification`, only final review in `final_review`, and no report change in `completed`. Reject a simultaneous canonical rebind with `completion_source_binding_invalid`. Revalidate the file at completion. Build completion from one closed canonical completion/source binding projection containing the run, Task Contract, artifact, staging, source, initial verification, initial review, final verification, final review, and the generation that enters `completed`; require all four report digests. Reject past-revision source rebinding and stale completion or final evidence after any source, artifact, or report change. Reuse one pure canonical inactive source projection in runtime, save, load, and every historical generation; require every inactive field and shadow connection flag to match exactly. In shadow mode, reuse one pure accepted-shadow Policy projection in the producer, semantic validation, and historical replay. Require source status to equal `execution_policy.source_sync.external_disconnected_status`, manual handoff to equal `manual_activation`, no overwrite, and external connection `unverified`/false. Reject rehashed status or handoff drift with `completion_source_binding_invalid`; never trust caller connection flags or hashes.

Require the closed Run State schema to list every persisted canonical field and close the nested team, selection, grants, Findings/resolution receipts, reports, source, artifacts, metrics, start request, and input problem projection shapes. Persist a Registry snapshot binding, exact `role_assignments`, sanitized input problems, and a canonical start request with their digests. Recompute the immutable run identity from that authority at load. Perform canonical selection replay with `select_team` and `plan_waves` when no input problem blocked team formation; otherwise require the exact empty team/grant/ownership/profile/wave projection. Rejoin every primary/quality assignment, write grant, and quality grant, including immutable roles, domains, capabilities, path scopes, model profile, phase, actor, and generation.

Follow the root commit pointer through every parent manifest. Validate the root and every historical manifest against the closed schema before reading integer/path fields, evaluating the anchor, or running semantic replay. Require contiguous revisions, exact parent generation/manifest/state/artifact bindings, immutable start inputs, and exact append-only prefixes for trace, Finding, failure history, implementation/resolution/artifact receipts, proposals, rejections, blockers, and conflicts. Regenerate all artifacts from each Run State; require `specialist-findings` receipts/catalog/conflicts and implementation metrics content to match their refs and manifest digests. Bind every failure to a real historical report generation and require its report snapshot, grant, artifact, plan/revision/attempt/cause, and Finding clause/location/source/digest to agree. For an identity with a resolution receipt, additionally require the resolution and fix receipt issue IDs to agree; keep every identity without one open. Recompute a closed metrics projection from state, team, waves, history, source, and completion; reject unknown or caller-supplied timing fields and keep unavailable measurements `unavailable`. Recompute every persisted quality report digest and validate its exact evidence, checks, provenance, and final staging/source revision. Treat rehashed semantic corruption, any missing/unknown field, or load-time mismatch as a structured blocked integrity failure; never backfill it in a constructor.

At load, use schema-first validation and do not invoke semantic replay for a schema-invalid Run State; convert unexpected semantic validator exceptions to a generic non-secret integrity failure. Replay selection even when a formed persisted team is empty. Rebuild every new artifact receipt as the canonical raw receipt projection of its immutable raw content, prior committed exact grant, generation, and provenance. Require one-to-one failure history derived from its report/cause/generation and causally resolved or still-open Findings. Use the same pure dedicated state gate for runtime transitions and persisted trace replay. For any generation containing a reserved transition, require exactly one such transition at the new trace suffix end and require it to equal final `run.state`. Bind closed reserved evidence to run, generation, transition, Task Contract, artifact, staging/source, completion, a non-cyclic gate projection, and only the transition-specific cause/report/Finding/receipt/failure/rejection/blocker/conflict generation-new evidence. Derive a closed target-specific causality projection with the reason/cause digest, report phase/kind/status/digest, Finding identity, receipt/failure/conflict digest, and rejection/blocker code. Authorize `blocked`, `failed`, and `needs_human_approval` only from their Policy-defined same-generation causes. Replay each historical generation from its prior state with that same pure predicate; reject missing, borrowed, unrelated, relocated, wrong-report, or later-generation evidence. Validate every generation's historical staging containment, existence, content digest, manifest/source digest, source-basis carry, and final-report bindings.

Maintain the root pointer and local commit anchor within one local trust boundary. Detect root-only rewind, anchor-only rewind, interrupted corruption, and manifest/artifact/state/receipt/source/completion inconsistencies. Treat a coherent coordinated rewind of the root, anchor, and referenced old generation by an equally privileged actor as out of scope; do not claim it is detected, prevented, or safe. Do not introduce an external append-only ledger, TPM/OS monotonic store, signature/MAC keys, or unapproved secrets. Leave an external trust anchor as a future extension only. Ignore pre-pointer crash orphans and recover only an exact next child after a post-pointer/pre-anchor crash.

Use `python3 scripts/team_harness.py legacy-adapt INPUT.json` only for a legacy single-agent envelope. Registry and Execution Policy constructors never backfill missing canonical values; this explicitly enabled adapter boundary is the only legacy conversion path. The command consults the same Registry and Execution Policy and executes the common core; unknown agents and a disabled adapter return non-zero. Never bypass team selection, independent verification and review, persistence, or completion gates.
