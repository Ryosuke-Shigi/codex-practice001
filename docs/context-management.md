# Context Management

- Status: active
- Scope: `Ryosuke-Shigi/codex-practice001`
- Last reviewed: 2026-07-10

## このドキュメントの目的

必要な文脈だけを読み、正確性と調査コスト削減を両立するための方針を定めます。
情報を減らすこと自体を目的にせず、正本、対象見出し、対象ファイルを作業へ正しく接続し、次回も安全に理解を再起動できる状態を作ります。

具体的な入口、読むdocs、読まないdocs、停止条件は [MDルーター](ai/workflows/md-router.md) を正本とし、この文書では再掲しません。

## 基本方針

- リポジトリ全体や全docsを毎回読み込まない
- 作業種別と対象を先に固定する
- 正確性に必要な正本、対象見出し、対象ファイルを確認する
- 読む範囲だけでなく、読まない範囲と編集しない範囲も固定する
- 長文docsは対象作業に関係する見出しから読む
- 最大ファイル数や最大行数などの固定上限で必要情報を削らない
- 検索して入口を特定し、直接依存が判明した場合だけ範囲を広げる
- 不明な前提を推測で補わない
- 同じ詳細ルールを複数docsへ貼り直さない
- 1タスクへ複数目的を混ぜない
- 作業後は検証済み事実だけを正しい戻し先へ反映する

## 文脈の決め方

1. 作業目的、対象repo、対象階層を確定する
2. MDルーターで作業プロファイルを選ぶ
3. 読む、条件付きで読む、読まない、編集しない範囲を固定する
4. プロファイルで指定された順序と条件に従い、feature / project docs、共通docs、対象コードの必要箇所を読む
5. 名前、Route、Class、Test、エラー、変更ファイルから入口を検索する
6. 直接依存が判明した場合だけ、理由を明示して範囲を追加する

`docs/index.md` は正本、docs配置、docs体系、文書Statusを確認するときに使います。通常作業で毎回読む文書にはしません。

## 探索範囲

目的なく `app/`、`resources/`、`tests/`、`docs/features/` 全体を探索しません。
無関係なDocker、本番、CI、Storage、Migration、Queue、Scheduler文書を「念のため」で読みません。

検索の手がかり:

- 機能名、画面名、Route名
- Controller、Action、Service、Repository、DTO、Responder
- Component、Hook、Test
- 明示されたエラー文、変更ファイル
- MDルーター、共通docs、feature docsからの直接参照

手がかりが不足し、作業継続に仕様判断が必要な場合は、repo全体探索で補完せず停止します。

## 正本と矛盾

用途別の正本は [docs/index.md](index.md) で確認します。
正本以外には短い要約とリンクだけを置き、機能固有仕様は該当feature docsへ残します。

次の場合は自動的に優先順位を決めません。

- 共通docs同士が矛盾する
- feature docsが共通ルールを上書きしている
- docsと現在コード・成功テストが矛盾する
- Git管理docsとローカル補助ハーネスが矛盾する
- `active / archived / superseded` の扱いが不明

矛盾している資料、確認済み範囲、進められない理由、次に必要な判断を報告します。

## 1タスクの範囲

```text
1目的
1機能または1ユースケース
必要なレイヤー一式
1ブランチ
1Pull Request
```

同じ目的を成立させるために不可分な実装、テスト、docs更新は同じタスクへ含められます。目的が異なる変更は分けます。

## 理解再起動

理解再起動は、会話ログや一時作業メモを保存することではありません。
次回作業者が現在のコード、型、コメント、テスト、docsから、目的、責務、入力、出力、禁止事項、変更時の注意を回収できる状態を作ることです。

残す候補:

- 現在の状態、機能の目的、入口
- 主要責務、処理フロー、DTOやpropsの形
- テストで固定した仕様と確認結果
- 壊しやすい導線、注意点、未完了事項
- 次に読む正本、feature docs、対象ファイル

反映先:

| 情報 | 主な反映先 |
|---|---|
| 複数機能に共通する判断基準 | 該当する共通docs |
| 機能固有の目的・制約・条件 | 該当feature docs |
| 実行可能な仕様 | コード、型、コメント、テスト |
| 作業結果と未実行理由 | PR Summary |
| 作業後の戻し先判断 | `docs/ai/workflows/work-result-feedback-loop.md` |

未確認の事実、一時的な会話条件、個人メモを正本化しません。

## Git管理docsとローカル情報

Git / branch / commit / PRの正本は `docs/ai/rules/agent-working-policy.md`、コマンドとrepo境界は `docs/operations/command-registry.md` とします。この文書へ詳細手順を複製しません。

`.local/` や `.local-rules/` は存在する場合だけ、該当するローカル環境差分の確認に使います。
ローカル情報を製品仕様、共通ルール、PR本文へ転記せず、Git管理外ファイルをstageしません。秘密情報や個人情報はlocalメモにも残しません。

## 停止条件

- 作業種別、対象機能、入口を特定できない
- 必要な仕様または正本を判断できない
- docs、コード、テスト、指示が矛盾する
- 対象外ファイル、別repo、本番、秘密情報、破壊的操作へ影響する
- 確認コマンドを確定できない
- ローカル情報をGit管理docsへ移さないと成立しない
- 検証できない状態で完了判定が必要になる

## 作業完了時

- 読む範囲を必要以上に広げていないか
- 必要な正本、feature docs、対象コードを読み漏らしていないか
- 複数目的や目的外変更を混ぜていないか
- 推測で前提を補っていないか
- 詳細ルールを重複記載していないか
- [work-result-feedback-loop.md](ai/workflows/work-result-feedback-loop.md) で戻し先を確認したか
- 理解再起動に必要な検証済み事実が正しい場所に残っているか
- ローカル情報や秘密情報がGit管理差分へ混ざっていないか

```text
情報を減らすことが目的ではない。
必要な文脈だけを、必要な時に、正しい入口から読み込む。
```
