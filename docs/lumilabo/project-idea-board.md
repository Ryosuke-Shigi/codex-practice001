# LumiLabo 案件システム IDEA BOARD

- Status: active
- Scope: LumiLabo / 案件システム IDEA BOARD
- Last reviewed: 2026-07-06
- Canonical source: この文書と `/lab/lumilabo-project-idea-board` のタブ構成

## 目的

LumiLabo 案件システム IDEA BOARD は、お客様に LumiLabo と案件システムの考え方を説明する資料として扱う。

LumiLaboは案件管理機能そのものではなく、複数のサブシステムを置ける上位プロダクト / 上位ドメインである。
最初に扱うサブシステムが案件システムであり、案件を起点に登録、一覧、詳細、将来の工程候補へ広がる考え方を説明する。

これはPRODUCT実装ではない。
MOCK、DB、Backend本実装、API通信、カレンダー、工程デッキ実装、工程カード実装は扱わない。
現行MOCKは別画面 `/lab/lumilabo-project-mock` で扱い、このIDEA BOARD内には実画面導線を置かない。

## 画面構成

IDEA BOARD画面は次の上位タブを基本にする。

1. 概要
2. フロー
3. 機能説明
4. 画面候補
5. 図解
6. グラフ
7. code

初期表示は概要とする。
上位タブは説明テーマの切り替え、薄いファイルタグは選択中テーマ内の説明切り替えに使う。
選んだタブとタグの内容だけを表示し、全内容を1枚に縦並びで表示しない。

薄いファイルタグは、リーフレットや書類フォルダの上に少し出ているような薄いタグ型にし、本文領域を圧迫しない。
横に収まらない場合は横スクロールを許容する。

## 概要

概要タブでは、LumiLaboと案件システムの位置づけを説明する。

見せること:

- LumiLabo は上位プロダクトである
- 案件システムは最初のサブシステムである
- 後から別サブシステムが並ぶ余地がある
- 工程デッキ、工程カード、横断カレンダーは拡張候補であり、確定PRODUCT仕様ではない

## フロー

フロータブでは、次の流れをフローチャートとして見せる。

```text
LumiLabo
  ↓
案件システム
  ↓
案件登録
  ↓
案件一覧
  ↓
案件詳細
  ↓
将来の工程デッキ
  ↓
将来の工程カード
```

案件詳細、工程デッキ、工程カードは後続候補として扱う。
実装済み導線と未確定の将来候補を混同しない。

現在の最初のMOCKでは、TOP → 選択 → 案件TOP → 登録 / 一覧 までを初期範囲として扱う。
案件詳細は、後続候補であり現在の標準タブには含めない。

## 機能説明

機能説明タブでは、案件システムで扱う初期情報と状態を説明する。

登録画面で扱う入力項目:

- 会社名
- 担当者名
- 住所
- メモ

一覧 / 詳細 / 進行管理側の表示候補:

- 登録日表示
- ステータス表示

登録日表示は登録画面の入力 / 表示項目ではない。
登録日時 / 登録日表示は、将来PRODUCTでは `created_at` 表示相当として一覧 / 詳細側で表示する候補として扱い、登録画面には表示しない。
ステータス表示は登録画面の入力 / 表示項目ではない。
ステータス表示は、一覧 / 詳細 / 進行管理側の表示候補として扱い、登録画面には表示しない。
住所は初期段階ではテキスト入力として扱い、郵便番号 / 都道府県 / 市区町村へ勝手に分割しない。
案件名は初期固定項目へ追加しない。

案件ステータス初期案:

- 進行中
- 完了
- 終了

完了は、必要な業務フローを通り切った状態として扱う。
終了は、キャンセル、失注、対象外など途中で閉じた状態を含み得る。
キャンセル / 失注を初期ステータスとして増やさない。
このステータス初期案は登録画面で選択させる仕様ではなく、一覧 / 詳細 / 進行管理側で状態を表示する将来候補として扱う。

## 工程デッキ / 工程カード

案件から見積 / 元調 / 請求 / 発注を直接 hasMany でぶら下げるだけの説明にしない。
案件と各カードの間に、工程デッキまたは同等の実体を挟む考え方を説明する。

工程デッキは、初回対応、追加対応、別ルート対応などを分けられる構造候補として扱う。
工程カードは、見積、元調、請求、発注などを後から追加できる候補として扱う。

工程カード状態:

- 未実行
- スルー
- 実行済

スルーは未実行ではなく、この案件では不要なものとして明示した状態として説明する。
完了判定は画面側ではなく、将来PRODUCT段階ではService側に置く考え方として補足する。
今回、Service実装はしない。

## 画面候補

画面候補タブでは、次のMOCKフェーズで確認する導線と画面候補を説明カードとして整理する。
画面そのものを作り込まない。

現在の最初のMOCKで確認する導線:

- TOP
- 選択
- 案件TOP
- 登録
- 一覧

後続候補:

- 案件詳細

フォームUI、一覧UI、詳細UIを実画面レベルで作らない。
画面候補は「次のMOCKフェーズで確認する画面」として説明する。

## 図解

図解タブでは、次を見せる。

- LumiLabo が上位プロダクトであること
- その下に案件システムがあること
- 後から別システムが並ぶ余地があること
- 共通カレンダー / 横断ビューは将来候補であり、初期PRODUCT仕様ではないこと
- 案件 → 工程デッキ → 工程カード の構造
- 見積 / 元調 / 請求 / 発注が工程カードとして扱われる考え方

## グラフ

グラフタブでは、実績データに見えない概念グラフを使う。
売上、件数、割合などを実績値として断定しない。

見せる候補:

- 案件から工程カードへ広がる情報量のイメージ
- 未実行 / スルー / 実行済の見え方イメージ
- 将来的な横断ビューで見える情報量のイメージ

グラフには「概念図」「イメージ」と分かる表現を入れる。

## code

`code` タブは補助であり、IDEA BOARDの主役にしない。

扱うこと:

- 既存導線の短い確認
- React Componentの責務境界
- 将来PRODUCT段階での責務分離の考え方
- 今回作らないもの

扱わないこと:

- 実装コードの大量掲載
- DB / Migration / API / Backend層
- 未確認の実装名やDB構造の確定
- 完了判定や業務状態判断のReact Component実装

## 作らないもの

- MOCK画面
- 実画面リンク集
- TOP / 選択 / 案件TOP / 登録 / 一覧 / 案件詳細の実UI
- 固定データ付き一覧MOCK
- 入力フォームMOCK
- 保存可能フォーム
- Reactフォーム実装
- DB / Migration / Model
- Controller / Request / Action / Service / Repository / DTO の本実装
- Event / Listener / Job / Scheduler
- API通信
- Docker変更
- 本番反映
- 工程デッキ実装
- 工程カード実装
- カレンダータブ
- カレンダーMOCK

## 確認観点

- 上位タブが 概要 / フロー / 機能説明 / 画面候補 / 図解 / グラフ / code であること
- 薄いファイルタグが本文領域を圧迫していないこと
- IDEA BOARDが画面そのものではなく、お客様向けの機能説明資料として読めること
- フローチャート、図解、グラフ、説明文があり、文章だけで埋まっていないこと
- codeタブが補助に留まっていること
- このIDEA BOARD内で TOP / 選択 / 案件TOP / 登録 / 一覧 / 案件詳細をMOCK画面として作っていないこと
- 現行MOCKの初期範囲が TOP / 選択 / 案件TOP / 登録 / 一覧 であり、案件詳細を標準タブにしていないこと
- 登録画面で扱う入力項目が会社名 / 担当者名 / 住所 / メモであること
- 登録日表示を登録画面の入力 / 表示項目として扱っていないこと
- ステータス表示を登録画面の入力 / 表示項目として扱っていないこと
- 案件名を初期項目へ追加していないこと
- 住所を勝手に分割していないこと
- キャンセル / 失注を初期ステータスとして増やしていないこと
- 工程デッキ、工程カード、カレンダーなどを未確定のPRODUCT仕様として断定していないこと
- DB / Migration / Backend本実装へ踏み込んでいないこと
