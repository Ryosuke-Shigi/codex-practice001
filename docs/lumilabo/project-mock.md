# LumiLabo 案件システム MOCK

- Status: active
- Scope: LumiLabo / 案件システム MOCK
- Last reviewed: 2026-07-12
- Canonical source: `/lab/lumilabo-project-mock` の初期導線と画面範囲

## 目的

LumiLabo 案件システム MOCK は、お客様に実際の画面導線を見てもらうための仮UIとして扱う。

IDEA BOARDは機能説明資料、MOCKは画面確認であり、MOCK側へIDEA BOARDの通常リンクや説明資料への戻り導線を置かない。

現在のMOCKでは、TOPから案件システムへ入る最小導線を維持しつつ、一覧から案件詳細へ進む最小導線と案件詳細単体のUIを確認する。

## 現在の導線

```text
TOP
  ↓ Start
選択
  ├ 案件 → 案件TOP
  │          ├ 登録 → 戻る → 案件TOP
  │          └ 一覧 → 戻る → 案件TOP
  │             └ 案件行 / 案件カード選択 → 案件詳細 → 戻る / 削除後 → 一覧
  └ TOPへ戻る → TOP
```

## 画面構成

全体タブ:

- TOP
- 選択

案件内タブ:

- TOP
- 登録
- 一覧

案件TOP通常ボタン:

- 登録
- 一覧
- 戻る

案件詳細は案件内タブではなく、一覧などから進む内部表示として扱う。戻るもファイルタグへ混ぜず、案件詳細内の通常ボタンとして戻り元へ戻す。現在は一覧から詳細へ入るため戻り元は list とし、戻る / 削除後は同じ戻り先制御で一覧へ戻す。

工程デッキ、工程カード、カレンダーは、ユーザーが明示した段階で追加する。現在の標準タブには含めない。

## TOP

TOPでは、LumiLaboの入口だけを見せる。

見せるもの:

- LumiLaboアイコン
- LumiLaboタイトル
- Startボタン

置かないもの:

- 案件説明
- IDEA BOARDリンク
- 一覧 / 登録 / 詳細への直接導線
- 実データに見える数値や進捗

## 選択

選択では、LumiLabo配下のサブシステムを選ぶ。

現在見せるもの:

- Primaryの案件ボタン / 案件カード
- SecondaryのTOPへ戻るボタン

現在は、案件以外のサブシステムを増やさない。
TOPへ戻るはMOCK内のUI状態をTOPへ戻すだけで、DB保存、API通信、Inertia遷移、route追加は行わない。

## 案件TOP

案件TOPでは、案件システムに入ったことと、案件内で確認する画面を見せる。

見せるもの:

- 案件アイコン
- 案件タイトル
- 登録 / 一覧 の通常ボタン
- 選択画面へ戻るボタン

戻るボタンは案件TOPに置き、選択画面へ戻る。登録画面と一覧画面では、画面内の通常ボタンとして案件TOPへ戻るボタンを置く。

## 登録

登録タブでは、案件登録画面の System UI MOCK を確認する。

現在の登録タブで扱う項目:

- 会社名
- 担当者名
- 住所
- メモ

会社名、担当者名、住所、メモは入力UIとして見せる。
住所は1つの入力項目として扱い、郵便番号 / 都道府県 / 市区町村へ勝手に分割しない。
登録するボタンの次に、案件TOPへ戻るボタンを置く。

登録タブで扱わないもの:

- 登録日時
- 登録日表示
- ステータス表示
- ステータス選択
- 案件名
- 郵便番号
- 都道府県
- 市区町村
- 住所の分割入力
- DB保存
- API通信
- Inertia送信
- 保存可能な本番フォーム
- Controller / Request / Action / Service / Repository / DTO / Responder の本実装

登録画面はMOCKであり、PRODUCTの保存フォームではない。
登録ボタンはMOCK上の見た目に留め、DB保存、API通信、Inertia送信、保存後遷移は行わない。

## 一覧

現在のMOCKでは、一覧は案件内の画面選択として扱う。

一覧では、案件を選択するための最小固定データ1件を置く。会社名を主表示として維持し、同じ1行で `担当者：〇〇` と `メモ：メモの内容の一部` を表示する。メモ全文は一覧へ広げず、省略表示に留める。

通常ボタンの「詳細を見る」は置かない。案件行 / 案件カード自体を `button` として扱い、クリックまたはキーボード操作で案件詳細へ進める。一覧から詳細へ進む場合、戻り元は `list` としてMOCK内部stateに保持する。

案件詳細フォーム、地図風プレビュー、写真撮影、ファイルD&D、保存ボタンは一覧へ混ぜない。

### 一覧拡張の実装停止

固定20件を対象にした一覧検索・登録日順・Paginationは、端末別の表示件数、担当者名の表示開始幅、初期登録日順が人間に承認されるまで実装しない。現行MOCKは上記の最小固定データ1件による一覧を維持する。

一覧拡張を再開する場合に反映する確定済み要件:

- 固定MOCKデータは20件とし、検索対象は会社名、担当者名、住所、メモにする。
- 半角・全角スペースを扱い、複数語はAND検索にする。
- 並び替え基準は登録日のみとし、新しい順と古い順を切り替えられるようにする。
- 一覧行には会社名と登録日を表示し、住所とメモは表示しない。
- Paginationは `＜＜` と `＞＞` だけを使い、複数ページの場合だけ表示する。
- Laravel側で検索・登録日順・ページ分割を行い、Inertia Partial Reloadでは `projectList` だけを再取得する。
- 選択した案件を案件詳細へ渡し、DB、本番API、本番CRUDには進まない。

未確定のため実装・テスト・確定仕様として扱わない項目:

- モバイル、タブレット、PCそれぞれの1ページ表示件数
- 担当者名を一覧行へ表示し始める端末幅
- 初期表示時の登録日順

## 案件詳細

案件詳細は一覧とは別の内部表示として扱う。詳細はファイルタグへ追加しない。

現在の案件詳細で扱う項目:

- 会社名
- 担当者名
- 住所
- メモ
- 登録日
- 地図風プレビュー
- 写真撮影ボタン
- ファイル複数ドラッグアンドドロップ欄
- 保存済み写真プレビュー
- 保存済みファイルプレビュー
- 案件削除ボタン
- 削除確認ダイアログ

会社名、担当者名、住所、メモはReact内stateで編集する。登録日は表示のみで、編集対象や保存対象にしない。

保存ボタンは、会社名、担当者名、住所、メモのいずれかが編集された場合だけ画面上部へ表示する。未編集時は状態を表示しない。表示が必要な時だけ「編集中」「保存中です」「保存しました」を文字で示し、保存完了の表示は自動で消す。保存はMOCK上のReact内state反映に留める。

保存完了検知は、MOCKでは `setTimeout` による擬似保存完了でよい。PRODUCT化時は `saveRequestId` / `jobId` と短時間pollingを検討し、レスポンス成功だけを写真・ファイルを含む全保存完了として扱わない。

地図風プレビューは基本情報の住所入力欄直下に置く。入力中の住所が空欄の場合は表示せず、空の枠も置かない。入力中の住所をURLエンコードして https://www.google.com/maps/search/?api=1&query=... を別タブで開く。Google Maps API、Geocoding API、Embed APIは使わない。

保存済み写真、保存済みファイルは存在する場合だけ見出しとプレビューを表示する。各プレビュー右上に `×` 削除を表示し、クリックするとMOCK上のReact stateから該当プレビューを表示削除する。0件の場合は見出し、枠、空表示を出さない。

案件詳細の戻るは、現在の一覧から入る導線では「案件一覧へ戻る」と表示する。案件詳細の一番下には、保存ボタンと場所・意味を分けて案件削除ボタンを置く。押下時は「この案件を削除しますか？」の確認ダイアログを表示し、「いいえ」は閉じるだけ、「はい」はMOCK上で案件を削除扱いにして、戻るボタンと同じ戻り先制御で戻す。現在は一覧から詳細へ来るため一覧へ戻る。将来カレンダーから詳細へ来た場合にも戻せるよう、削除実行後の戻り先を一覧に直書きしない。

保存済み写真 / ファイル削除と案件削除はMOCK上の表示削除に留める。DB削除、API削除、S3削除は行わない。

## 確認観点

- TOP → Start → 選択 → 案件 → 案件TOP の導線になっていること
- 選択で案件とTOPへ戻るを選べること
- 選択のTOPへ戻るでTOPへ戻れること
- TOPは LumiLabo / Start の入口だけになっていること
- 選択はPrimaryの案件ボタン / 案件カードとSecondaryのTOPへ戻るボタンだけになっていること
- 案件内タブが TOP / 登録 / 一覧、案件TOP通常ボタンが 登録 / 一覧 / 戻る であること
- 案件TOPはモバイル縦で上寄せ、スマホ横では通常ボタンと戻るが見切れないこと
- 登録 / 一覧画面の戻るが通常ボタンで、ファイルタグへ混ざっていないこと
- 登録 / 一覧画面の戻るで案件TOPへ戻れること
- 登録タブで会社名 / 担当者名 / 住所 / メモが表示されること
- 登録タブに登録日時 / 登録日表示が出ていないこと
- 登録タブにステータスが出ていないこと
- 登録タブに案件名が出ていないこと
- 住所が分割入力になっていないこと
- 案件TOPの戻るボタンで選択へ戻れること
- 詳細が案件内タブへ追加されていないこと
- 戻るが案件内タブへ追加されていないこと
- 一覧に案件詳細フォーム、地図風プレビュー、写真撮影、ファイルD&D、保存ボタンが混ざっていないこと
- 一覧に「詳細を見る」ボタンが出ていないこと
- 一覧で会社名を主表示にし、担当者とメモの一部が1行で表示されること
- 一覧のメモ全文が広がらず省略表示になること
- 案件行 / 案件カードクリック、またはキーボード操作で案件詳細へ進めること
- 一覧から案件詳細へ進む場合、戻り元が `list` としてMOCK内部stateに保持されること
- 案件詳細の戻るで戻り元へ戻れること
- 案件詳細で会社名 / 担当者名 / 住所 / メモを編集できること
- 案件詳細の保存ボタンは編集後だけ表示されること
- 案件詳細の保存後に「保存しました」が上部に表示され、自動で消えること
- 登録日は編集不可で、保存対象外であること
- 地図風プレビューがGoogle Maps検索URLを別タブで開くこと
- Google Maps API / Geocoding API / Embed APIを使っていないこと
- 写真撮影ボタンがPC / タブレット / モバイルで表示されること
- 保存済み写真 / ファイルの各プレビュー右上に `×` 削除が表示されること
- `×` 削除でMOCK上のReact stateから該当プレビューが表示削除されること
- 保存済み写真 / ファイルが0件の場合は見出し、枠、空表示が出ないこと
- 案件詳細の一番下に案件削除ボタンがあること
- 案件削除ボタンで `この案件を削除しますか？` の日本語確認ダイアログが出ること
- 「いいえ」は確認ダイアログを閉じるだけであること
- 「はい」はMOCK上で案件を削除扱いにし、戻るボタンと同じ戻り先制御で戻ること
- 削除後の戻り先を一覧に直書きしていないこと
- Backend / DB / API / S3削除へ踏み込んでいないこと
- IDEA BOARDへの通常リンクをMOCK内に置いていないこと
- スマホ横置きで案件TOPの戻るボタンが見切れないこと
- DB / Backend本実装 / API通信へ踏み込んでいないこと
