# LumiLabo 案件システム MOCK

- Status: active
- Scope: LumiLabo / 案件システム MOCK
- Last reviewed: 2026-07-15
- Canonical source: `/lab/lumilabo-project-mock` の初期導線と画面範囲

## 目的

LumiLabo 案件システム MOCK は、お客様に実際の画面導線を見てもらうための仮UIとして扱う。

IDEA BOARDは機能説明資料、MOCKは画面確認であり、MOCK側へIDEA BOARDの通常リンクや説明資料への戻り導線を置かない。

現在のMOCKでは、TOPから案件システムへ入る最小導線を維持しつつ、一覧から案件詳細へ進む最小導線と案件詳細単体のUIを確認する。

## 現在の導線

```text
TOP
  ↓ Start
選択
  ├ 案件 → 案件TOP
  │          ├ 登録 → 戻る → 案件TOP
  │          └ 一覧 → 戻る → 案件TOP
  │             └ 案件行 / 案件カード選択 → 案件詳細 → 戻る / 削除後 → 一覧
  └ TOPへ戻る → TOP
```

## 画面構成

全体タブ:

- TOP
- 選択

案件内タブ:

- TOP
- 登録
- 一覧

案件TOP通常ボタン:

- 登録
- 一覧
- 戻る

案件詳細は案件内タブではなく、一覧などから進む内部表示として扱う。戻るもファイルタグへ混ぜず、案件詳細内の通常ボタンとして戻り元へ戻す。現在は一覧から詳細へ入るため戻り元は list とし、戻る / 削除後は同じ戻り先制御で一覧へ戻す。

工程デッキ、工程カード、カレンダーは、ユーザーが明示した段階で追加する。現在の標準タブには含めない。

## TOP

TOPでは、LumiLaboの入口だけを見せる。

見せるもの:

- LumiLaboアイコン
- LumiLaboタイトル
- Startボタン

置かないもの:

- 案件説明
- IDEA BOARDリンク
- 一覧 / 登録 / 詳細への直接導線
- 実データに見える数値や進捗

## 選択

選択では、LumiLabo配下のサブシステムを選ぶ。

現在見せるもの:

- Primaryの案件ボタン / 案件カード
- SecondaryのTOPへ戻るボタン

現在は、案件以外のサブシステムを増やさない。
TOPへ戻るはMOCK内のUI状態をTOPへ戻すだけで、DB保存、API通信、Inertia遷移、route追加は行わない。

## 案件TOP

案件TOPでは、案件システムに入ったことと、案件内で確認する画面を見せる。

見せるもの:

- 案件アイコン
- 案件タイトル
- 登録 / 一覧 の通常ボタン
- 選択画面へ戻るボタン

戻るボタンは案件TOPに置き、選択画面へ戻る。登録画面と一覧画面では、画面内の通常ボタンとして案件TOPへ戻るボタンを置く。

- 住所
- メモ

登録するボタンの次に、案件TOPへ戻るボタンを置く。

登録タブで扱わないもの:

- 登録日時
- 登録日表示
- ステータス表示
- ステータス選択
- 案件名
- 郵便番号
- 都道府県
- 市区町村
- 住所の分割入力
- DB保存
- API通信
- Inertia送信
- 保存可能な本番フォーム
- Controller / Request / Action / Service / Repository / DTO / Responder の本実装

登録画面はMOCKであり、PRODUCTの保存フォームではない。
登録ボタンはMOCK上の見た目に留め、DB保存、API通信、Inertia送信、保存後遷移は行わない。

## 一覧

一覧は案件内の画面選択として扱う。ControllerがQuery Actionを実行し、Query ActionがLaravel側の固定20件からreadonly item DTO群を生成してListDTOへ格納し、Controllerへ返す。ControllerはListDTOをResponderへ渡し、Responderが初回GETのInertia Props `projectList.items`へ固定20件すべてを変換する。DB、外部API、S3、本番CRUDには接続しない。

`projectList` は20件の `items` だけを持つ。検索条件、並び順、ページ、表示件数、削除済みID、保存済み基本情報override、再取得URLはpropsに含めない。検索、登録日順、Pagination、表示件数計測、保存override、削除除外はReact内で完結し、初回itemsから一覧を導出する。

登録日は初期表示で新しい順（`registered_desc`）とし、古い順（`registered_asc`）へ切り替えられる。同じ登録日の案件は固定データの定義順を維持する。検索、登録日順、ページ切替、表示件数変更はすべてReact state内で完結し、一覧操作によるInertia Partial Reloadや追加通信は行わない。

検索対象は会社名、担当者名、住所、メモである。半角・全角スペースで分割した複数語をAND条件として扱い、検索ボタンを押した時だけ適用する。入力中は通信しない。適用中の検索条件だけを表示し、解除時は登録日順を維持して1ページ目へ戻る。

検索モーダルは文字付きの「検索」と「閉じる」を使う。モバイルのDOM順は「検索」「閉じる」、sm以上では「閉じる」「検索」とする。通信状態に依存せず、送信時にだけ条件を適用して閉じる。

1ページの表示件数はクライアント内だけの `ResizeObserver` 計測で更新してよい。計測不能時も安全な初期表示件数で20件を保持し、loadingや通信へ遷移しない。

一覧行は1件1行の `button` とし、会社名と登録日を必ず表示する。担当者名は行コンテナの幅に余裕がある場合だけ補助情報として表示する。住所、メモ、ステータス、一致理由は通常行へ表示しない。通常ボタンの「詳細を見る」は置かない。

Paginationは複数ページの場合だけ一覧フィールド下へ置き、`＜＜` と `＞＞` だけを使う。Chevron、ページ番号、総件数、現在ページ表示は追加しない。前後ページがない操作はdisabled属性で操作不可にする。0件時は一覧フィールド内の日本語表示だけにし、Paginationは表示しない。

選択した案件IDを保持して案件詳細へ渡す。検索条件、登録日順、現在ページ、表示件数は、一覧タブ内の一覧と詳細の内部遷移で保持する。React内の基本情報下書き、保存済み基本情報、保存済み写真、保存済みファイル、選択・ドロップしたファイル、削除済みIDは案件ID単位のstateで保持し、案件間で混在させない。保存・削除後も一覧は同じstateから直ちに再導出される。ページ末尾削除で現在ページが範囲外なら、保持した一覧stateのまま有効な最終ページへ補正し、全件削除時は0件、1ページ目、Paginationなしとなる。削除は同一セッション内だけで、DB、外部API、S3には保存しない。

## 案件詳細

案件詳細は一覧とは別の内部表示として扱う。詳細はファイルタグへ追加しない。

現在の案件詳細で扱う項目:

- 会社名
- 担当者名
- 住所
- メモ
- 登録日
- 地図風プレビュー
- 写真撮影ボタン
- ファイル複数ドラッグアンドドロップ欄
- 保存済み写真プレビュー
- 保存済みファイルプレビュー
- 案件削除ボタン
- 削除確認ダイアログ

会社名、担当者名、住所、メモ、保存済み写真、保存済みファイル、選択・ドロップしたファイルは選択案件IDごとのReact内stateで編集・表示する。登録日は表示のみで、編集対象や保存対象にしない。初回表示には既存fixtureを使い、案件単位のstateを作成した後は共通fixtureで上書きしない。

保存ボタンは、会社名、担当者名、住所、メモのいずれかが編集された場合だけ画面上部へ表示する。未編集時は状態を表示しない。表示が必要な時だけ「編集中」「保存中です」「保存しました」を文字で示し、保存完了の表示は自動で消す。保存はMOCK上のReact内state反映に留める。

会社名は必須とし、空または空白だけの場合はMOCK保存を開始せず、入力欄に日本語エラーを表示する。担当者名、住所、メモは空欄を許可する。

保存完了検知は、MOCKでは `setTimeout` による擬似保存完了でよい。保存中も編集、保存済み写真・ファイル削除、ファイル選択・ドロップは継続できるため、保存開始時の案件IDだけを完了対象とし、完了時は最新の案件stateを破壊しない。現在表示中の案件IDと一致する場合だけ詳細表示を更新する。保存中の案件を削除した場合はそのタイマーを無効化し、削除済み案件を復活させない。PRODUCT化時は `saveRequestId` / `jobId` と短時間pollingを検討し、レスポンス成功だけを写真・ファイルを含む全保存完了として扱わない。

地図風プレビューは基本情報の住所入力欄直下に置く。入力中の住所が空欄の場合は表示せず、空の枠も置かない。入力中の住所をURLエンコードして https://www.google.com/maps/search/?api=1&query=... を別タブで開く。Google Maps API、Geocoding API、Embed APIは使わない。

写真撮影ボタンからは、モバイル・タブレット向けの全画面連続撮影UIを開く。MOCKでも `navigator.mediaDevices.getUserMedia` で実カメラを起動し、背面カメラを優先する。背面カメラを利用できない場合は利用可能なカメラへフォールバックし、複数カメラを検出できた場合だけ前面・背面の切替操作を有効にする。切替、閉じる、Component破棄では利用中の `MediaStreamTrack` を停止する。実カメラ確認はHTTPSまたはlocalhostのsecure contextを前提とする。

シャッター操作では現在のvideoフレームをCanvasへ描画し、BlobとObject URLを生成して撮影順のままブラウザメモリ内へ一時保持する。撮影するたびに画面遷移せず、枚数表示と横スクロールのサムネイルを更新して連続撮影を続けられる。サムネイルまたは「撮影を終了して確認」から同じ写真確認ビューを開き、選択写真を拡大表示する。確認ビューでは対象写真だけを即時削除し、削除したObject URLを解放する。最後の1枚を削除した場合は撮影画面へ戻る。

撮影写真は案件の保存済み写真へ追加せず、画面再読み込みまたは撮影Featureの破棄で消える。残っているObject URLもFeature破棄時に解放する。S3、DB、Laravel API、Action、Service、Repository、DTO、Event、Listener、Jobには接続しない。「撮影を終了して確認」は結果確認までとし、保存確定ボタンや未確定の次画面を追加しない。PRODUCT化時は1枚ずつの保存と非同期削除へ進める予定だが、圧縮品質、最大長辺、EXIF補正、保存用ファイル名はこのMOCKでは確定しない。

カメラ許可拒否、カメラ未検出、他アプリによる使用中、カメラAPI非対応、撮影画像生成失敗は日本語で区別して表示する。再試行できる状態では再試行導線を出し、閉じる操作を維持する。カメラを利用できない場合は既存のファイル選択へ戻れる。PCでも既存のファイル選択、プレビュー、削除表示を維持し、撮影UIへ自動で置き換えない。

保存済み写真、保存済みファイルは存在する場合だけ見出しとプレビューを表示する。各プレビュー右上に `×` 削除を表示し、クリックすると対象案件IDのMOCK上React stateからだけ該当プレビューを表示削除する。0件の場合は見出し、枠、空表示を出さない。

案件詳細の戻るは、現在の一覧から入る導線では「案件一覧へ戻る」と表示する。案件詳細の一番下には、保存ボタンと場所・意味を分けて案件削除ボタンを置く。押下時は「この案件を削除しますか？」の確認ダイアログを表示し、「いいえ」は閉じるだけ、「はい」は選択案件IDだけをMOCK上で削除扱いにして、戻るボタンと同じ戻り先制御で戻す。現在は一覧から詳細へ来るため一覧へ戻る。将来カレンダーから詳細へ来た場合にも戻せるよう、削除実行後の戻り先を一覧に直書きしない。

保存済み写真 / ファイル削除と案件削除はMOCK上の表示削除に留める。DB削除、API削除、S3削除は行わない。
