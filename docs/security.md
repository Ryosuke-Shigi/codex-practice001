# Security

- Scope: `Ryosuke-Shigi/codex-practice001`

## このドキュメントの目的

このドキュメントは、秘密情報、本番環境、AIエージェント、重要操作、外部公開、ログ出力の安全境界を定めます。

AIへの指示文だけを安全装置とは扱わず、権限、接続先、実行経路を分離して、誤操作できる範囲そのものを限定します。

## 基本方針

- AIを開発の主体にしない
- 仕様確定、責務境界、本番反映、完成判定、テスト済み判定は人間が行う
- AIには調査、実装補助、差分修正、テスト観点整理、レビュー補助を任せる
- AI出力をそのまま採用せず、差分、テスト、実行対象を人間が確認する
- 実行できることと、実行してよいことを分ける

## 秘密情報

次の実値を、AGENTS.md、README、docs、Skills、指示用まとめ、PR本文、コメント、ログへ記載しません。

- `.env` の実値
- APIキー、Authorization header
- DBパスワード
- SSH秘密鍵・接続情報
- AWSアクセスキー
- Cookie、Session、Token
- 個人情報

ドキュメントへ記載してよいのは、環境変数名、用途、取得元の種類、必須・任意、安全な設定手順までです。

`.env.example` にはキー名と安全な例だけを記載します。

## 環境と接続先

- production、staging、localの接続情報を分離する
- 本番 `.env` をAIエージェントへ渡さない
- AIエージェントが本番サーバーや本番DBへ直接接続できる状態を標準にしない
- ローカル用の認証情報を本番で使い回さない
- 接続先が不明な状態でDB構造変更、重要データ操作、外部API更新を行わない

本番操作が必要な場合は、対象環境、対象サービス、実行内容、影響範囲を人間が確認します。

## AIエージェントの権限境界

AIエージェントは、原則として読み取り、差分作成、テスト実行を中心に使います。

人間が判断するもの:

- 本番反映
- DB設計の確定
- 重要データへ影響する操作
- 外部APIへの更新・取消リクエスト
- secretsの追加・変更
- テスト結果を根拠とした完成判定
- Pull Requestのmerge

書き込みを許可する場合も、作業ブランチ、変更対象、実装しないこと、確認コマンドを先に固定します。

## 重要操作

次の操作は、人間が対象環境と影響範囲を確認した場合だけ扱います。

- DB全体またはテーブル全体へ影響する操作
- 本番データの一括変更
- Docker volumeへ影響する操作
- 本番ストレージやバックアップへ影響する操作
- 本番向け外部APIの更新・取消

実装する場合は、対象条件の決定をService、取得・永続化をRepositoryへ分離し、テストで対象範囲を固定します。

## DB権限

- DBユーザーは環境と用途に応じて分離する
- アプリケーション実行に不要な権限を付与しない
- 調査が読み取りだけで足りる場合は、読み取り権限を使用する
- 開発用・調査用の接続へ不要な構造変更権限を持たせない
- バックアップを本番DBと同じ影響経路だけに置かない

具体的なユーザー名、パスワード、接続文字列は記載しません。

## Dockerと外部公開

外部公開は、利用者がアクセスするために必要な入口だけに限定します。

公開対象:

- HTTP: 80
- HTTPS: 443
- SSH: 22（運用上必要な場合のみ）

原則として直接公開しない対象:

- MySQL
- Redis
- Adminer
- Mailpit Web UI / SMTP
- MinIO管理画面

ローカル開発用サービスをhostへ公開する場合は、必要に応じて `127.0.0.1` に限定します。

## ログ

ログへ次を記録しません。

- APIキー、Authorization header
- `.env` 実値、DBパスワード
- Cookie、Session、Token
- 個人情報
- 外部APIレスポンス全文
- 巨大payload

ログ分類と出力責務は `docs/logging.md` に従います。

## 外部API

- 取得と更新・取消を区別する
- API quota、rate limit、対象件数を確認する
- 更新・取消系は対象条件と冪等性をテストする
- timeout、部分失敗、再実行時の挙動を固定する
- 外部レスポンスを信用せず、必要な形式検証を行う

## レビュー項目

- 秘密情報が差分へ含まれていない
- 接続先と対象環境が明確
- AI権限が必要範囲に限定されている
- 重要操作の対象条件がServiceとテストで固定されている
- 外部公開ポートが必要最小限
- ログへ秘密情報や巨大payloadを含めていない
- バックアップと復旧経路を説明できる
