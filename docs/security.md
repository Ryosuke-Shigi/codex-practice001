# Security

- Status: active
- Scope: `Ryosuke-Shigi/codex-practice001`
- Last reviewed: 2026-06-10

## このドキュメントの目的

このドキュメントは、このプロジェクトにおける秘密情報、本番環境、AIエージェント、破壊的操作、外部公開、ログ出力の安全境界を明文化するためのものです。

AIへの指示文だけを安全装置とは扱わず、権限・接続先・実行経路を分離して、AIが誤操作できる範囲そのものを限定します。

## 基本方針

- AIを開発の主体にしない
- 仕様確定、責務境界、本番反映、完成判定、テスト済み判定は人間が行う
- AIには、調査、実装補助、差分修正、テスト観点整理、レビュー補助を任せる
- AIの出力をそのまま採用せず、差分・テスト・実行対象を人間が確認する
- 「実行できること」と「実行してよいこと」を分ける

## 秘密情報の扱い

以下の実値を、AGENTS.md、README、docs、Skills、指示用まとめ、PR本文、コメント、ログへ記載しません。

- `.env` の実値
- APIキー
- DBパスワード
- SSH秘密鍵・接続情報
- AWSアクセスキー
- Authorization header
- Cookie、Session、Token
- 個人情報

ドキュメントへ記載してよいのは、環境変数名、用途、取得元の種類、必須・任意、設定手順までです。

`.env.example` にはキー名と安全な例だけを記載し、実際の認証情報は入れません。

## 環境と接続先の分離

- production、staging、local の接続情報を分離する
- 本番 `.env` をAIエージェントへ渡さない
- AIエージェントが本番サーバーや本番DBへ直接接続できる状態を標準にしない
- ローカル開発用の認証情報を本番で使い回さない
- 接続先が不明な状態で、migration、削除、外部API更新を実行しない

本番操作が必要な場合は、対象環境、対象サービス、実行コマンド、影響範囲を人間が確認してから実行します。

## AIエージェントの権限境界

AIエージェントは、原則として読み取り・差分作成・テスト実行を中心に使います。

次の判断は人間が行います。

- 本番反映
- DB設計の確定
- 破壊的操作の実行
- 外部APIへの更新・削除リクエスト
- secrets の追加・変更
- テスト結果を根拠とした完成判定
- Pull Request の merge

AIエージェントへ書き込みを許可する場合も、作業ブランチ、変更対象、実装しないこと、確認コマンドを先に固定します。

## 破壊的操作

以下は、人間の明示確認なしに実行しません。

- `php artisan migrate:fresh`
- `php artisan db:wipe`
- `DROP DATABASE`、`DROP TABLE`
- 本番データに対する一括 `DELETE`、`TRUNCATE`
- `docker compose down -v`
- `docker system prune`
- `docker volume prune`
- 本番ストレージやバックアップの削除
- 本番向け外部APIの削除・更新操作

削除処理を実装する場合は、対象条件の決定をService、取得・削除をRepositoryへ分離し、必要なテストで対象範囲を固定します。

## DB権限

- DBユーザーは環境と用途に応じて分離する
- アプリケーション実行に不要な権限を付与しない
- 開発用・調査用の接続に、不要な `DROP` 権限を持たせない
- 読み取りだけで足りる調査では、読み取り権限を使用する
- バックアップを本番DBと同じ破壊経路だけに置かない

具体的なDBユーザー名、パスワード、接続文字列はこのドキュメントに記載しません。

## Dockerと外部公開

外部公開は、利用者がアクセスするために必要な入口だけに限定します。

外部公開対象:

- HTTP: 80
- HTTPS: 443
- SSH: 22（運用上必要な場合のみ）

原則として外部公開しない対象:

- MySQL
- Redis
- Adminer
- Mailpit Web UI
- Mailpit SMTP

ローカル開発用サービスをポート公開する場合は、必要に応じて `127.0.0.1` に限定します。

## ログへ記録しない情報

以下をログへ記録しません。

- APIキー
- Authorization header
- `.env` 実値
- DBパスワード
- Cookie、Session、Token
- 個人情報
- 外部APIレスポンス全文
- 巨大payload

ログの分類、保存先、保持期間、レイヤーごとの責務は `docs/logging.md` に従います。

## バリデーション

- フロントエンドバリデーションは、入力ミスを早く伝えるために使う
- バックエンドはLaravelのFormRequest / Requestで必ず検証する
- フロントエンドだけで安全とは判断しない
- 直接リクエスト、改ざん、API実行を前提にバックエンドを最終防衛線とする

## GitHubとレビュー

- `main` へ直接pushしない
- featureブランチからPull Requestを作成する
- 差分、CI / status check、秘密情報混入、docs更新有無を確認してからmergeする
- secrets、認証情報、未加工の本番データをcommitしない
- 誤って秘密情報をcommitした場合は、削除commitだけで完了とせず、認証情報を失効・再発行する

## 変更時の確認項目

- 秘密情報の実値が差分に入っていないか
- 本番環境へ直接接続する経路が増えていないか
- AIエージェントの権限が必要以上に広がっていないか
- 破壊的操作が人間確認なしで実行されないか
- DBユーザーへ不要な権限を追加していないか
- MySQL、Redis、Adminer、Mailpitを外部公開していないか
- ログへ秘密情報、個人情報、巨大payloadを出していないか
- バックエンドバリデーションを省略していないか
- 必要なテストと差分レビューを実施したか
